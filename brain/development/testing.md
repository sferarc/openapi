# Testing

Every test runs with vitest and offline: each one stubs or injects `fetch`, so none calls a real API. Run one package with `pnpm turbo run test --filter=<package>` (the root `pnpm test` hands extra arguments to its trailing `vitest run`, which rejects `--filter`). Nothing has to be built first: the clients with Effect bindings extend the root `vitest.shared.ts`, which aliases `@sferadev/openapi-utils` and `@sferadev/openapi-utils/effect` to `packages/openapi-utils/src`, so `pnpm exec vitest run` inside a client works on a clean checkout and sees edits to openapi-utils without a rebuild. Builds still bundle openapi-utils from its `dist`. The list below was checked against `git ls-files '*.test.ts'` on 2026-10-15.

## Clients

- `src/client.test.ts`, in every client: `request()` percent-encodes path parameters, rejects a missing one before calling `fetch`, calls an endpoint without parameters and rejects an unknown endpoint (#26). `litellm-api`'s copy also reaches untagged operations through the `default` namespace (#24). `cloudflare-api-js`'s copy also checks that `GET /zones` sends its `explode: false` `type` array as `type=full%2Cpartial` and that `GET /organizations` keeps `id=a&id=b` (`.changeset/delimited-query-params.md`). It also checks that both Worker script uploads send `multipart/form-data` without a `Content-Type` of their own, with the `metadata` part as JSON and each module as a named `File` part (`.changeset/cloudflare-worker-multipart-upload.md`). The seven clients with a `client.api` proxy (all but `keycloak-api`) also check that `Object.prototype` names such as `constructor`, `toString` and `hasOwnProperty` are neither tags nor operations, while a real operation is still a function. Every client checks that `config.headers` passed to `request()`, and to `client.api` where it exists, reach `fetch` next to the client's `Authorization` header. Each also holds `@ts-expect-error` lines, never run, that `pnpm tsc` checks: `request()`, and `client.api` where it exists, reject a `pathParams` missing its key and an unknown top-level key, and `vercel-api-js` accepts header parameters under `headers` (`.changeset/typed-call-params-*.md`).
- The OAuth helpers on `client.auth` are tested in the same files (#30): `vercel-api-js` `accessToken`, and `refreshToken` in `netlify-api`, `cloudflare-api-js` and `zoom-api-js`. Each test asserts the URL, method, headers including `Authorization`, the body encoding and the mapped result, and what a non-2xx response does: Vercel and Netlify reject with the status, Zoom rejects with an `Error` naming it, and Cloudflare resolves the raw `Response` for the caller to check. The Cloudflare test pins `https://dash.cloudflare.com/oauth2/token` and a form-encoded body (`.changeset/cloudflare-oauth-token-endpoint.md`).
- `src/utils/fetcher.test.ts`, in every client: the hand-written fetcher surfaces an HTTP error with its status (#8); query strings omit nullish values, repeat a key for each array item and encode reserved characters (#16); a 204 or an empty JSON body resolves to `undefined`, and a lowercase `authorization` or `content-type` header replaces the default (#28); a non-JSON error body such as a proxy's HTML 502 is kept as raw text up to 1000 characters, and a failed request rejects with an `Error` whose message names the method, the path without its query string and the reason, with the original exception as `cause`, while an aborted request rejects with the `AbortError` itself and a timed out one with the signal's `TimeoutError` rather than a wrapped `Error` (`.changeset/abort-reason-as-is.md`); a 204 with a JSON content type resolves to `undefined`. A binary response (`application/zip`) resolves to a `Blob` with its bytes intact, an empty `application/octet-stream` body to `undefined`, and a `text/csv` body stays a string (`.changeset/binary-responses-as-blob.md`). The `cloudflare-api-js`, `litellm-api` and `vercel-api-js` copies check that an `application/x-ndjson`, `application/jsonl` or `application/stream+json; charset=utf-8` body resolves to one value per line, with CRLF and blank lines (`.changeset/line-delimited-json-*.md`); `vercel-api-js`'s copy also calls `runSessionCommand` with an ndjson body and checks it resolves to the lines and is typed as `RunSessionCommandStatus200Json | RunSessionCommandStatus200XNdjson` (`expectTypeOf`, checked by `tsc`). `vercel-api-js`'s copy also checks that a generated operation percent-encodes its path parameters (#17). `v0-api`'s copy also checks that a request without a `baseUrl` goes to `https://api.v0.dev/v1` and one with a `baseUrl` goes there instead (`.changeset/v0-api-default-base-url.md`), and that an object query parameter is sent as `deepObject` keys and leaves out nullish entries (#119), and `cloudflare-api-js`'s copy that one is sent as a key per property, also without nullish entries (`.changeset/cloudflare-form-object-query.md`). The `vercel-api-js` and `v0-api` copies check that a generated operation (`createAccessGroup`, `chatsCreate`) sends its body as a JSON string with `Content-Type: application/json` ([[decisions/2026-10-27-keep-spec-keys]]). `netlify-api`'s copy also checks that deploy file paths keep their slashes (#23), and that an octet-stream upload is sent as raw bytes and a site build zip as multipart form data while JSON bodies stay JSON (#25).
- `src/effect.test.ts`, in the five published Effect clients (`netlify-api`, `nuki-api-js`, `v0-api`, `vercel-api-js`, `zoom-api-js`): an HTTP error becomes `ApiError` and a failed request becomes `NetworkError` (#8). `v0-api`'s copy also checks that a layer without `baseUrl` calls `https://api.v0.dev/v1`. `vercel-api-js`'s copy also checks that the `NetworkError` message carries the request and the reason.

## `@sferadev/openapi-utils`

Run alone with `pnpm turbo run test --filter=@sferadev/openapi-utils`.

- `src/kubb/spec-transforms.test.ts`: the spec transforms, stubbing the global `fetch` for `fetchSpec` (#18).
- `src/kubb/components/client-operation.test.ts`: `buildUrlTemplate` percent-encodes single-segment path parameters (#17), keeps slashes in file path parameters and does not double-encode a path already passed through `encodeURI` (#23).
- `src/kubb/client/operations.test.ts`: runs kubb with `createConfig` on the fixture `src/kubb/client/fixtures/params.json` into a temp directory, then imports the emitted `components.ts` against a stub fetcher and a fake `fetch`. The emitted signature types `pathParams`, `queryParams` and `headers` with the plugin-ts `GetMemberPath`, `Partial<GetMemberQuery>` and `Partial<GetMemberHeaders>` and contains no `unknown`, with a `$ref` (`Cursor`) and a `oneOf` (`status`) query parameter resolved in `types.ts`. A path parameter that is not a JS identifier (`team-id`) is read with bracket access and percent-encoded, a falsy required value (`0`) is kept, query and header params are forwarded, an array query parameter with `explode: false` is joined with `,` and one with `style: pipeDelimited` with `|` while a default one repeats its key, an operation without parameters works, a multipart body sends array items as repeated parts, an object as JSON, numbers and booleans as strings and leaves out a `null` field, a url-encoded body is sent as a `URLSearchParams` with its `Content-Type`, repeating the key for array items and sending an object as JSON, a `Blob` in a url-encoded body rejects before `fetch`, a url-encoded schema with a binary field (a `$ref` in the fixture) is sent as multipart, an `application/scim+json` body is sent as a JSON string with that `Content-Type`, a 200 that declares both `application/json` and `application/x-ndjson` (`runCommand`) is typed in `types.ts` as the union of the JSON body and an array of the line schema, a `Blob` response, a `text/plain` error, a `multipart/form-data` object response (as `string`) and an `application/scim+json` response are typed from their own media type, and a missing or empty path parameter, or an omitted `pathParams`, rejects with `Missing required path parameter` before `fetch` is called.
- `src/kubb/integers.test.ts`: runs kubb with `createConfig` on an inline spec and checks that `format: int64` fields and path parameters are typed `number`, not `bigint`, and that the emitted zod schema parses a JSON number into a number that `JSON.stringify` accepts.
- `src/kubb/plugin.test.ts`: `pluginClient` is a plugin extension named `plugin-client` that depends on `plugin-ts` and keeps its options, and defines `setup` with no `kubb:plugin:setup` hook (the kubb 5.11 shape, #51). The build itself is covered by `operations.test.ts`.
- `src/kubb/adapter.test.ts`: `requestBodyFallback` keeps the first raw media type (#25), keeps a url-encoded body, prefers an `application/scim+json` body over a raw one, and returns nothing for a body without a schema. `responseContentFallback` prefers an `application/scim+json` response over a raw one, keeps the first raw media type, types an `application/pdf` body as a `Blob` whatever its schema, types a `multipart/form-data` or `application/xml` object schema as `string` and keeps a `*/*` object schema, skips line-delimited JSON, leaves a response with an `application/json` entry alone and returns nothing without a body schema. `responseWithLineDelimitedJson` adds an ndjson variant typed as an array to a JSON response and leaves a response without an `application/json` body unchanged.
- `src/effect/proxy.test.ts`: the Effect proxies map a rejection with a `status` to `ApiError`, a missing path parameter to `ValidationError` naming the field and anything else to `NetworkError`, pass the `ApiConfig` service to the operation as `config`, and return `undefined` for an unknown tag, operation or endpoint (#33). They also abort the request signal when the effect times out, provide `fetchImpl` to the operation, and return `undefined` for `Object.prototype` keys (#46). A `param types` case checks with `@ts-expect-error` that an operation whose argument is optional keeps its param types in both proxies (`.changeset/typed-call-params-*.md`). A second case checks that such an operation can be called with no argument while one with a required `pathParams` cannot (`.changeset/effect-optional-params-*.md`).
- `src/effect/errors.test.ts`: how `ApiError.message` and `NetworkError.message` read each provider's error shape (#33).
- `src/kubb/client/extra.test.ts`: reads every package's committed `src/**/generated/components.ts` and asserts that each exported operation appears in `operationsByTag` (#24), and that every `Content-Type` an operation sends is a `type/subtype` media type, which `applicationJson` was not ([[decisions/2026-10-27-keep-spec-keys]]).

## Website

`@sferadev/openapi-website` tests the Vercel OAuth profile mapping in `apps/openapi/src/lib/vercel-user-info.test.ts` with an injected `fetch`, so it needs no `DATABASE_URL` or network: a missing access token or a failed request throws, the bearer token is sent, the nested `user` profile maps with `name` falling back to the email and a null avatar omitted, and an un-nested profile is rejected (#31). Run it with `pnpm turbo run test --filter=@sferadev/openapi-website`.

## Changeset script

`.github/workflows/scripts/changeset.test.ts` tests `changeset.ts`, the pure parts that `changes.ts` imports when `update-openapi.yml` writes a changeset: the diff summary, entry resolution and its fallbacks, and changeset rendering (#27). The root `pnpm test` runs it after the turbo tests (`package.json`).

## What is not tested

Beyond those tests, the checks on the clients are type-level and structural: `pnpm tsc` over the generated code and the hand-written client, `knip` for unused exports and dependencies, and `is-tree-shakable` on each built package ([[toolchain]]).

Generated output is not snapshot-tested. `extra.test.ts` reads the committed output and checks only that `operationsByTag` lists every operation; `operations.test.ts` generates from its own fixture and asserts mainly on how the emitted code runs. A regeneration is otherwise reviewed through its diff and the changeset `changes.ts` writes ([[architecture/pipeline]]).
