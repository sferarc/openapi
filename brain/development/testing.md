# Testing

`clickhouse-cloud` has tests: `packages/clickhouse-cloud/src/client.test.ts`, run with vitest and offline through an injected `fetch`. It covers the client, basic auth and the Effect bindings (#2), and the fetcher's failure paths: a non-JSON error body kept as raw text up to 1000 characters, and a failed request rejected as an `Error` naming the method and path with the original exception as `cause`.

`@sferadev/openapi-utils` unit-tests the spec transforms in `packages/openapi-utils/src/kubb/spec-transforms.test.ts` with vitest, stubbing the global `fetch` for `fetchSpec`. Run it alone with `pnpm test --filter=@sferadev/openapi-utils`.

Every other client except `clickhouse-cloud` has `src/utils/fetcher.test.ts`, which tests its hand-written fetcher offline with a stubbed `fetch`: an HTTP error status surfaces with that status (#8), a non-JSON error body such as a proxy's HTML 502 is kept as raw text up to 1000 characters, a failed request rejects with an `Error` whose message names the method, the path without its query string and the reason, with the original exception as `cause`, and query strings omit nullish values, repeat a key for each array item, and encode reserved characters (#16). Only `vercel-api-js`'s copy also checks that a generated operation percent-encodes its path parameters (#17). The five published Effect clients (`netlify-api`, `nuki-api-js`, `v0-api`, `vercel-api-js`, `zoom-api-js`) also have `src/effect.test.ts`, which checks that an HTTP error becomes `ApiError` and a failed request becomes `NetworkError` (#8); `vercel-api-js`'s copy also checks that the `NetworkError` message carries the request and the reason. Run one package with `pnpm test --filter=<package>`; turbo builds `@sferadev/openapi-utils` first, and running vitest directly in a client fails until it is built.

Beyond those tests, the checks on the clients are type-level and structural: `pnpm tsc` over the generated code and the hand-written client, `knip` for unused exports and dependencies, and `is-tree-shakable` on each built package ([[toolchain]]).

Generated output is not snapshot-tested. A regeneration is reviewed through its diff and the changeset `changes.ts` writes ([[architecture/pipeline]]). The changeset script's pure parts are tested in `.github/workflows/scripts/changeset.test.ts`, which the root `pnpm test` runs after the turbo tests.
