# Plans

The repository has no roadmap file and no open issues (checked 2026-10-24; #52 closed on 2026-10-21 and #15 on 2026-10-22). The first release publishes the eight existing clients ([[development/release]]). Known open work, from the sources cited:

1. First release from this repository, which waits on each package's npm trusted publisher and then on the owner setting `RELEASE_ENABLED`; the checklist and what the toggle triggers are in [[development/release]]. It ships the openapi-utils bundling fix (#1), the inlined Effect types (#4), the path encoding, raw body, untagged operation and `request()` fixes (#17, #23 to #26), the fetcher's empty body and header case fixes (#28), Zoom's basic auth token refresh (#30), the API's message in `ApiError` (#33), the failure cause and response body kept on fetcher errors (#37), the exported fetcher types in the `keycloak-api` and `v0-api` declarations (#42) and aborting the request when an Effect operation is interrupted (#46), the JSON request bodies of `vercel-api-js` and `v0-api` ([[decisions/2026-10-27-keep-spec-keys]]), the array and object fields of multipart bodies (#91), the url-encoded request bodies of `cloudflare-api-js`, `keycloak-api` and `litellm-api`, plus the spec updates merged in #56 to #61 and the spec source switch in #64, which is a major for `litellm-api`.
2. That first release is a major for every published client: the five Effect clients for Effect 4 ([[decisions/2026-10-08-effect-4-major]]), and all eight for the HTTP error shape change (#9, `.changeset/http-errors-as-api-error.md`). The full list of pending changesets is in [[development/release]].
3. Scheduled client regeneration, on since the owner set `SPEC_UPDATES_ENABLED` on 2026-10-26; no scheduled run had gone through at that point. #64 repointed the dead `litellm-api` and `zoom-api-js` spec URLs (merged 2026-10-21); each matrix job now has `timeout-minutes: 45`. kubb 5.13.1 (#72) brings the `cloudflare-api-js` generate from over 14 minutes without finishing to under a minute, and `cleanOperationIds` now renames a later operation whose ID collides with an earlier one, which unblocks the Cloudflare spec's two `deleteWebhook` operations. The scheduled runs on 2026-10-26 and 2026-10-27 generated every client but could not push, because `GIT_TOKEN` is dead; the workflow now mints a `sferarc-hq` App token, which works once sferarc/infra adds `openapi` to the selected repositories of `HQ_APP_ID` and `HQ_APP_PRIVATE_KEY`. Details in [[architecture/pipeline]].

The older clients' fetchers used to report an HTTP error status as `NetworkError` rather than `ApiError` (#6). #8 fixed that, and each Effect client's `src/effect.test.ts` asserts `ApiError` with the status (checked 2026-10-13).
