# Package layout

## Clients

Eight clients under `packages/`, listed in `README.md`: `cloudflare-api-js`, `keycloak-api`, `litellm-api`, `netlify-api`, `nuki-api-js`, `v0-api`, `vercel-api-js`, `zoom-api-js`. All eight are published.

A typical client (`packages/vercel-api-js/`):

| Path | Origin |
| --- | --- |
| `src/generated/` | Generated by [[pipeline]]. Never edit by hand: the next `pnpm generate` deletes it. |
| `src/utils/` | Hand-written fetcher, fetch types and helpers, one copy per package. They differ by API, for example bearer token in `vercel-api-js`. The generated operations carry only the path, so the fetcher holds the API's base URL: `v0-api`'s defaults to `https://api.v0.dev/v1`, the spec's server; before `.changeset/v0-api-default-base-url.md` it defaulted to `""`, so every call without a `baseUrl` fetched a relative URL such as `/chats`, in the published 0.3.1 too (`npm pack v0-api@0.3.1`, checked 2026-10-29). `litellm-api` and `keycloak-api` take the base URL as a required constructor option instead. The fetchers that accept a base URL (`cloudflare-api-js`, `keycloak-api`, `litellm-api`, `v0-api`, `vercel-api-js`) and `netlify-api`'s, which accepts a `basePath`, drop trailing slashes from it before appending the operation path, which always starts with `/`, and `KeycloakAccountApi` does the same before adding `/realms/<realm>`; before `.changeset/base-url-trailing-slash.md` a base URL such as `http://localhost:4000/` sent `http://localhost:4000//models` (the "without doubling it" cases in each `src/utils/fetcher.test.ts` and in `keycloak-api`'s `src/client.test.ts`). How each server answers a doubled slash is unknown, as none was tried. Every fetcher parses a JSON content type, resolves a binary one (`application/octet-stream`, `zip`, `gzip`, `x-tar`, `pdf`, `wasm`, `vnd.tcpdump.pcap`, and `image/*`, `audio/*`, `video/*`, `font/*`) as a `Blob` when the response has `blob()`, and returns anything else as text (`isBinary` in `src/utils/fetcher.ts`). Only the `keycloak-api` fetcher sends an `Accept` header by default, `application/json, */*;q=0.8`: Keycloak answers 406 when no `@Produces` of an endpoint matches it, so the `application/json` it sent before `.changeset/keycloak-accept-non-json.md` failed every call to the client certificate `download` and `generate-and-download` (`application/octet-stream`) and to the realm localization text (`text/plain`) (`@Produces` in `ClientAttributeCertificateResource.java` and `RealmLocalizationResource.java` of keycloak/keycloak, checked 2026-10-29). No request was tried against a Keycloak server. The generated operations encode each path parameter once with `encodeURIComponent`; `zoom-api-js`'s fetcher encodes a path segment a second time when it begins with `%2F` or contains `%2F%2F`, because the Zoom spec says a meeting or webinar UUID that begins with `/` or contains `//` must be double-encoded (the `meetingId`, `meetingUUID` and `webinarId` descriptions of 35 operations, such as `GET /past_meetings/{meetingId}`, checked 2026-10-30). A UUID the caller already encoded arrives as `%252F...`, so it is not encoded a third time (`doubleEncodeSlashedSegments` and its cases in `src/utils/fetcher.test.ts` and `src/client.test.ts`). Before `.changeset/zoom-double-encode-uuid.md` such a UUID went out encoded once. No request was tried against the Zoom API. The fetchers of `cloudflare-api-js`, `litellm-api` and `vercel-api-js`, whose specs declare line-delimited JSON responses, resolve `application/x-ndjson`, `application/ndjson`, `application/jsonl`, `application/jsonlines`, `application/x-jsonlines` and `application/stream+json` to an array with one parsed value per non-empty line (`isLineDelimitedJson`), where a single `JSON.parse` failed on the second line. The operations are Vercel's `listBillingCharges`, `listContractCommitments`, `getRuntimeLogs`, `runSessionCommand` and `getSessionCommandLogs` (and `getDeploymentEvents`, which also declares `application/json`), LiteLLM's Lens dataset export and Cloudflare's `getCollectionExportEndpoint` (specs checked 2026-10-28). The response types of the line-only operations are `unknown`; `runSessionCommand` and `getDeploymentEvents`, which also declare a JSON body, are typed as that body or the array of lines ([[shared-utils]]). The body is read whole, so a stream the server keeps open never resolves; whether Vercel closes `getRuntimeLogs` on its own is unknown, as it was not called against the API. The other five specs declare no such response. The fetchers of `cloudflare-api-js`, `keycloak-api`, `netlify-api` and `vercel-api-js`, whose generated operations accept a `ReadableStream` body, send it with `duplex: "half"`, which Node's `fetch` requires for a stream; the other four have no stream-typed operation (`grep ReadableStream src/generated`, checked 2026-10-28). |
| `src/client.ts` | Hand-written client class over `operationsByTag` and `operationsByPath`. `client.api` and `request()` look up own keys only (`Object.hasOwn`), so `Object.prototype` names such as `constructor` return `undefined` rather than a namespace or an operation wrapper; `keycloak-api` has no `client.api` proxy. Both spread the caller's `config` over the client's own `token`, `fetchImpl` and base URL or path, so per-call `headers` and `signal` reach the request (`#withConfig`, or `withConfig` in `keycloak-api`). `signal` is a field of `FetcherConfig` in every `src/utils/fetcher.ts`; before `.changeset/call-signal-*.md` it was only in `FetcherOptions`, so the fetcher passed a signal to `fetch` but `{ config: { signal } }` failed to compile, although each README says a call cancelled through `signal` rejects with the `AbortError`. Their params are typed as the operation's own argument with `NonNullable<Parameters<Operation>[0]>`: a generated operation defaults its argument to `{}`, so `Parameters` gives `params | undefined`, and the `Omit<..., keyof FetcherConfig>` used before collapsed that union to `{}` and accepted any params; it would also have dropped the header parameters, which share the name `headers` with `FetcherConfig` (`.changeset/typed-call-params-*.md`). Each `client.test.ts` guards this with `@ts-expect-error` lines that `pnpm tsc` checks. |
| `src/index.ts`, `types.ts`, `schemas.ts`, `components.ts` | Hand-written re-exports that become the package's entry points. |
| `src/effect.ts` | Effect bindings built with `createEffectApi` from [[shared-utils]]. |
| `kubb.config.ts` | Spec URL and fixups. |

Variations: `keycloak-api` has `src/admin/` and `src/account/`, each with its own `generated/`, `types.ts`, `schemas.ts` and `components.ts`, exported as `./admin/*` and `./account/*` in place of the root `types.ts`, `schemas.ts` and `components.ts` (`configs/knip.json`, `packages/keycloak-api/package.json`). `cloudflare-api-js` has no `schemas.ts`, and `cloudflare-api-js`, `keycloak-api` and `litellm-api` have no `effect.ts` or `./effect` entry (directory listings, `exports` in each `package.json`).

## Build and exports

`bunchee` builds each client into `dist/` with ESM, CJS and declarations, with `--dts-bundle` for the clients that have an `effect` entry so the shared Effect types are inlined (#4); `exports` maps `.`, `./types`, `./schemas`, `./components` and `./effect` where present (`packages/vercel-api-js/package.json`). The only runtime dependency is `zod`, except in `cloudflare-api-js`, which has none because it generates with `skipZod: true` (`packages/cloudflare-api-js/kubb.config.ts`). The five clients with an `effect` entry declare `effect ^4.0.0` as an optional peer; the other three declare no peers (`dependencies` and `peerDependencies` in each `package.json`, [[decisions/2026-10-08-effect-4-major]]). `is-tree-shakable` runs on every package in `pnpm check` (`package.json`).

`@sferadev/openapi-utils` is a devDependency of every client and is bundled into `dist/` rather than resolved at install time (#1, [[decisions/2026-10-08-bundle-openapi-utils]]).

## Configs

`configs/tsconfig` is the shared `@sferadev/tsconfig` workspace package. `configs/knip.json` lists entry points per workspace and ignores `src/generated/**`.
