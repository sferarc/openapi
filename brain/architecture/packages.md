# Package layout

## Clients

Eight clients under `packages/`, listed in `README.md`: `cloudflare-api-js`, `keycloak-api`, `litellm-api`, `netlify-api`, `nuki-api-js`, `v0-api`, `vercel-api-js`, `zoom-api-js`. All eight are published.

A typical client (`packages/vercel-api-js/`):

| Path | Origin |
| --- | --- |
| `src/generated/` | Generated by [[pipeline]]. Never edit by hand: the next `pnpm generate` deletes it. |
| `src/utils/` | Hand-written fetcher, fetch types and helpers, one copy per package. They differ by API, for example bearer token in `vercel-api-js`. Every fetcher parses a JSON content type, resolves a binary one (`application/octet-stream`, `zip`, `gzip`, `x-tar`, `pdf`, `wasm`, `vnd.tcpdump.pcap`, and `image/*`, `audio/*`, `video/*`, `font/*`) as a `Blob` when the response has `blob()`, and returns anything else as text (`isBinary` in `src/utils/fetcher.ts`). The fetchers of `cloudflare-api-js`, `keycloak-api`, `netlify-api` and `vercel-api-js`, whose generated operations accept a `ReadableStream` body, send it with `duplex: "half"`, which Node's `fetch` requires for a stream; the other four have no stream-typed operation (`grep ReadableStream src/generated`, checked 2026-10-28). |
| `src/client.ts` | Hand-written client class over `operationsByTag` and `operationsByPath`. `client.api` and `request()` look up own keys only (`Object.hasOwn`), so `Object.prototype` names such as `constructor` return `undefined` rather than a namespace or an operation wrapper; `keycloak-api` has no `client.api` proxy. Both spread the caller's `config` over the client's own `token`, `fetchImpl` and base URL or path, so per-call `headers` reach the request (`#withConfig`, or `withConfig` in `keycloak-api`). |
| `src/index.ts`, `types.ts`, `schemas.ts`, `components.ts` | Hand-written re-exports that become the package's entry points. |
| `src/effect.ts` | Effect bindings built with `createEffectApi` from [[shared-utils]]. |
| `kubb.config.ts` | Spec URL and fixups. |

Variations: `keycloak-api` has `src/admin/` and `src/account/`, each with its own `generated/`, `types.ts`, `schemas.ts` and `components.ts`, exported as `./admin/*` and `./account/*` in place of the root `types.ts`, `schemas.ts` and `components.ts` (`configs/knip.json`, `packages/keycloak-api/package.json`). `cloudflare-api-js` has no `schemas.ts`, and `cloudflare-api-js`, `keycloak-api` and `litellm-api` have no `effect.ts` or `./effect` entry (directory listings, `exports` in each `package.json`).

## Build and exports

`bunchee` builds each client into `dist/` with ESM, CJS and declarations, with `--dts-bundle` for the clients that have an `effect` entry so the shared Effect types are inlined (#4); `exports` maps `.`, `./types`, `./schemas`, `./components` and `./effect` where present (`packages/vercel-api-js/package.json`). The only runtime dependency is `zod`, except in `cloudflare-api-js`, which has none because it generates with `skipZod: true` (`packages/cloudflare-api-js/kubb.config.ts`). The five clients with an `effect` entry declare `effect ^4.0.0` as an optional peer; the other three declare no peers (`dependencies` and `peerDependencies` in each `package.json`, [[decisions/2026-10-08-effect-4-major]]). `is-tree-shakable` runs on every package in `pnpm check` (`package.json`).

`@sferadev/openapi-utils` is a devDependency of every client and is bundled into `dist/` rather than resolved at install time (#1, [[decisions/2026-10-08-bundle-openapi-utils]]).

## Configs

`configs/tsconfig` is the shared `@sferadev/tsconfig` workspace package. `configs/knip.json` lists entry points per workspace and ignores `src/generated/**`.
