# Package layout

## Clients

Nine published clients under `packages/`, listed in `README.md`: `clickhouse-cloud`, `cloudflare-api-js`, `keycloak-api`, `litellm-api`, `netlify-api`, `nuki-api-js`, `v0-api`, `vercel-api-js`, `zoom-api-js`.

A typical client (`packages/clickhouse-cloud/`):

| Path | Origin |
| --- | --- |
| `src/generated/` | Generated by [[pipeline]]. Never edit by hand: the next `pnpm generate` deletes it. |
| `src/utils/` | Hand-written fetcher, fetch types and helpers, one copy per package. They differ by API, for example bearer token in `vercel-api-js` and basic auth in `clickhouse-cloud`. |
| `src/client.ts` | Hand-written client class over `operationsByTag` and `operationsByPath`. |
| `src/index.ts`, `types.ts`, `schemas.ts`, `components.ts` | Hand-written re-exports that become the package's entry points. |
| `src/effect.ts` | Effect bindings built with `createEffectApi` from [[shared-utils]]. |
| `kubb.config.ts` | Spec URL and fixups. |

Variations: `keycloak-api` has `src/admin/` and `src/account/`, each with its own `generated/` (`configs/knip.json`). `cloudflare-api-js` has no `schemas.ts` or `effect.ts`, and `litellm-api` has no `effect.ts` (directory listings, `configs/knip.json`).

## Build and exports

`bunchee` builds each client into `dist/` with ESM, CJS and declarations; `exports` maps `.`, `./types`, `./schemas`, `./components` and `./effect` where present (`packages/clickhouse-cloud/package.json`). Runtime dependencies are `zod` only, with `effect ^3` as an optional peer. `is-tree-shakable` runs on every package in `pnpm check` (`package.json`).

`@sferadev/openapi-utils` is a devDependency of every client and is bundled into `dist/` rather than resolved at install time (#1, [[decisions/2026-10-08-bundle-openapi-utils]]).

## Configs

`configs/tsconfig` is the shared `@sferadev/tsconfig` workspace package. `configs/knip.json` lists entry points per workspace and ignores `src/generated/**`.
