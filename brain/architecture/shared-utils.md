# Shared utils

`packages/openapi-utils` (`@sferadev/openapi-utils`) is private and unpublished (`"private": true` in its `package.json`; `npm view` returns 404). Clients bundle it ([[decisions/2026-10-08-bundle-openapi-utils]]).

## Entry points

- `.` (`src/index.ts`): the kubb side, used only at generation time.
  - `baseConfig` and `createConfig({ outputPath, importPath, skipZod })` (`src/kubb/index.ts`). The adapter's `dateType` is `stringOffset`, so plugin-zod writes a `format: date-time` field as `z.iso.datetime({ offset: true })`, which accepts any RFC 3339 offset (`Z`, `+00:00`, `+02:00`), and plugin-ts still types it as `string` (`src/kubb/dates.test.ts`). With `string`, the earlier value, the schemas used `z.iso.datetime()`, which accepts only `Z`, so `2026-10-30T12:00:00+00:00` failed to parse in the 498 date-time schemas of `litellm-api`, `netlify-api`, `nuki-api-js`, `v0-api`, `vercel-api-js` and `zoom-api-js` (`.changeset/date-time-offsets.md`). A local regeneration of `nuki-api-js` on 2026-10-30 changed nothing but those calls. A value without any offset still fails, as RFC 3339 requires one; which of these APIs send offsets other than `Z` is unknown, as none was called. The adapter maps every integer, `format: int64` included, to `number` (`integerType: "number"`), and plugin-zod to `z.int()`: kubb's default, `bigint`, typed 658 fields and parameters of `cloudflare-api-js`, `keycloak-api`, `netlify-api`, `nuki-api-js` and `zoom-api-js` as `bigint` (and `z.coerce.bigint()`) although `JSON.parse` gives a number, and a `bigint` in a JSON body, such as the `ttl` of Netlify's `createDnsRecord`, makes `JSON.stringify` throw. A value above `Number.MAX_SAFE_INTEGER` loses precision; whether any of these APIs sends one is unknown (`src/kubb/integers.test.ts`).
  - `adapterOasWithRawBodies` (`src/kubb/adapter.ts`) wraps `adapterOas`. With `contentType: "application/json"` the adapter drops every other media type, so operations that only accept a non-JSON body had no `body` parameter. The wrapper parses a second time without `contentType` and copies one request body onto those operations only, a JSON type such as `application/scim+json` first and otherwise the first media type with a schema; JSON operations are unchanged (`requestBodyFallback`). The operation component types such a body as `Blob | ArrayBuffer | Uint8Array | ReadableStream | string` and multipart bodies as a `FormData` built from the fields (`formDataBlock` in `src/kubb/components/client-operation.tsx`): a string or `Blob` is appended as is, a number, boolean or bigint as a string, an object as a JSON string, an array as one part per item under the same name, and a `null` or `undefined` field is left out. Before #91, array and object fields were dropped, so Cloudflare's `workerScriptPutContent` and `workerVersionsUploadVersion` sent neither `files` (`Blob[]`) nor `metadata` (an object), and LiteLLM's image edits sent no `image` (`Blob[]`); the committed clients carry the fix from their next scheduled regeneration. Whether Cloudflare reads the modules from parts named `files`, as its spec describes, is unknown: no upload was tried against the API. An `application/x-www-form-urlencoded` body is typed as the spec's schema and sent as a `URLSearchParams` with that content type, with the same rules per field (`urlEncodedBlock`); the fetchers pass it to `fetch` as is, since they only stringify bodies whose `Content-Type` is `application/json`. Form fields cannot carry a file, so a url-encoded schema with a binary (`format: binary`, a `Blob` in the types) field anywhere in it, refs followed, is generated as multipart instead (`requestContentType`), and a `Blob` that still reaches `urlEncodedBlock` throws `Cannot send the file in field <key> as application/x-www-form-urlencoded` rather than being sent as `%7B%7D`. Before this, url-encoded bodies were left out of the fallback, so the operations that only accept one had no `body`: Keycloak's organization `invite-user` and `invite-existing-user`, LiteLLM's OAuth `/token`, `/{mcp_server_name}/token`, `/introspect`, `/revoke` and `/authorize/complete`, and Cloudflare's brand protection logo upload (specs checked 2026-10-28). The logo upload's `image` is `type: string, format: binary`, so it is the one that becomes multipart; whether Cloudflare accepts a multipart upload there is unknown, as no upload was tried, and its docs and official SDK send `application/x-www-form-urlencoded` (`cloudflare/cloudflare-typescript` `src/resources/brand-protection/logos.ts`, checked 2026-10-28). A local regeneration of the three clients on 2026-10-28 produced the Keycloak and LiteLLM operations as url-encoded and the Cloudflare one as multipart, and all three typechecked. The committed clients get the `body` at their next scheduled regeneration. A JSON type other than `application/json` (`application/scim+json`, `application/merge-patch+json`, `application/json; charset=utf-8`) is typed as the spec's schema and sent through `JSON.stringify` with its own `Content-Type` (`isOtherJson`), since the fetchers stringify only `application/json`. Before this, the fallback skipped every JSON-like type and the JSON parse keeps only `application/json`, so Cloudflare's `scimUsersCreate`, `scimUsersPatch`, `scimUsersPut`, `scimGroupsCreate`, `scimGroupsPatch` and `scimGroupsPut`, whose only body is `application/scim+json`, had no `body` (spec checked 2026-10-28); `cloudflare-api-js` gets it at its next regeneration. The same wrapper types the responses the JSON parse leaves as `unknown` because the spec declares no `application/json` for them (`responseContentFallback`): it takes the fallback parse's content for that status code, a JSON type first and otherwise the first media type with a schema. A JSON type such as `application/scim+json`, or `*/*` (where the server picks, and Keycloak's `mapper-types` sends JSON), keeps the spec's schema. A media type the fetchers resolve as a `Blob` (the `isBinary` list of [[packages]]) is typed as `Blob` whatever its schema says, since Cloudflare declares its PDF, PNG and KV value downloads and LiteLLM its skill archive as a plain `type: string`. Any other media type is typed as `string`, because the fetchers return its body from `response.text()`: a `text/plain` string schema stays as it is, and Cloudflare's `multipart/form-data` snippet content (`getZoneSnippetContent`), whose spec schema is an object of files, is `string` rather than an object a caller could index into (#117 review). Line-delimited JSON on its own (`application/x-ndjson`, `application/jsonl`, `application/stream+json`, `application/json-seq`) is skipped: its schema describes one line, not the body. A local regeneration on 2026-10-28 typed `chatsDownloadVersion` in `v0-api` as `Blob` and its `text/event-stream` `chatsResume` as `string`, `readSessionFile` in `vercel-api-js`, LiteLLM's skill archive and Keycloak's certificate download as `Blob`, Keycloak's localization text as `string`, and the success responses of the Cloudflare spec that declare no `application/json`, and every regenerated client typechecked; `netlify-api` and `nuki-api-js` did not change, and the `zoom-api-js` spec declares no such response. The committed clients get the types at their next scheduled regeneration. plugin-zod writes such a `Blob` as `z.instanceof(File)`, which a `Blob` fails; no client validates responses with its schemas. The one exception is a line-delimited JSON variant (`application/x-ndjson`, `jsonl`, `stream+json` and the other types the fetchers split per line) next to an `application/json` body in the same response: `responseWithLineDelimitedJson` copies it from the second parse as an array of its line schema, because the fetcher resolves such a body to an array, and plugin-ts then emits the status type as a union of `<Name>Status200Json` and, for example, `<Name>Status200XNdjson`. A response with only a line-delimited type keeps the `unknown` placeholder. In the specs checked on 2026-10-28 this applies to Vercel's `runSessionCommand` (`{ command }`, or the status and log lines with `wait: true`) and `getDeploymentEvents` (an array of events either way); Cloudflare's and LiteLLM's line-delimited responses have no JSON variant.
  - `pluginClient` (`src/kubb/plugin.ts`) with its generators in `src/kubb/client/` and the operation component in `src/kubb/components/`. kubb 5 stable dropped `@kubb/plugin-client`, so the plugin shell lives here (comment in `plugin.ts`). Since kubb 5.11 it is declared with `defineExtension({ kind: "plugin", meta, setup })` and typed with `PluginType`, the same shape `@kubb/plugin-ts` uses: 5.11 removed `PluginFactoryOptions` from `kubb/kit`, and its `definePlugin` takes a definition object rather than a function of the options, so the old shell failed the type check and crashed at config load (#51).
    - Tag namespaces (`src/kubb/client/extra.tsx`, #24): an operation without a tag goes under `default` in `operationsByTag` and `tagDictionary`, so `client.api.default` and the Effect `ApiService.default` reach it. Each tag is lower-cased and camel-cased into a key, and tags that land on the same key (Cloudflare's `brand_protection` and `Brand Protection`) share one namespace; before #24 the last such tag replaced the others. An operation with several tags appears under each.
    - Parameter types (`resolveTypeSchemas` in `src/kubb/components/client-operation.tsx`): `pathParams`, `queryParams` and `headers` are typed with the grouped `<Operation>Path`, `<Operation>Query` and `<Operation>Headers` types `@kubb/plugin-ts` emits into `types.ts` (`resolver.param.path`, `query`, `headers`), imported next to the body and response types. Header params are wrapped in `Partial<>`, so they stay optional as before, although the spec requires some (Cloudflare's `If-Match` on the spend policy update and delete, Vercel's `Content-Length` on the artifact upload, checked 2026-10-30). Query params are wrapped in `Partial<>` only when none is required; otherwise `queryParams` is required and typed with `<Operation>Query`, so a required field such as `chatId` on `v0-api`'s `GET /deployments` must be passed (`.changeset/required-query-params.md`). Before, every query param was optional, which typed 104 operations in `cloudflare-api-js`, 57 in `vercel-api-js`, 27 in `litellm-api`, 13 in `netlify-api`, 12 in `zoom-api-js` and one in `v0-api` as callable without a parameter the API requires. The component used to print its own inline type per parameter, which turned every `$ref`, `oneOf`/`anyOf` union and object schema into `unknown` (5,747 occurrences in the committed `cloudflare-api-js` `components.ts`, 1,277 in `litellm-api`, 62 in `vercel-api-js`, checked 2026-10-28). Clients pick this up at their next regeneration (`.changeset/param-types-from-spec.md`).
    - Delimited query parameters (`delimitedQueryParams` in `src/kubb/components/client-operation.tsx`): a query parameter with an array schema (refs and unions followed) and `explode: false`, or `style: spaceDelimited` or `pipeDelimited` without `explode: true`, is joined with `,`, ` ` or `|` before the fetcher sees it, as OpenAPI serializes it; every other array still goes out as repeated keys (`type=full&type=partial`), the default form explode. The fetchers build the query with `URLSearchParams`, so the comma goes out as `%2C`. Before this, the 15 such parameters in the live Cloudflare spec, on 12 operations (checked 2026-10-29), were sent as repeated keys, although the spec asks for one comma-separated value: `type` on `zonesGet` (`?type=full,partial`), the required `ids` on `getZonesZoneIdentifierZarazConfigHistory`, `fields` on `d1GetDatabase`. `id` on `GET /organizations` is the exception: its description asks for repeated keys (`id=foo&id=bar`), so `packages/cloudflare-api-js/kubb.config.ts` sets `explode: true` on it. Whether Cloudflare also accepts repeated keys on the other 14 parameters is unknown, as no request was tried against the API; the other seven live specs have no such parameter. The committed `cloudflare-api-js` was regenerated with the change, which touched only those 11 operations in `components.ts` (2026-10-29, `.changeset/delimited-query-params.md`).
    - Path parameters (`buildUrlTemplate` in `src/kubb/components/client-operation.tsx`, #17, #23): a parameter named `path`, `file_path` or `filepath` (any case) is encoded segment by segment, keeping slashes and existing `%XX` escapes, so file paths and values already passed through `encodeURI` arrive unchanged. Every other path parameter goes through `encodeURIComponent` in full.
  - Spec transforms (`src/kubb/spec-transforms.ts`): `fetchSpec` (throws on a timeout, a network failure, a non-OK status, a non-JSON body or a body without an `openapi`/`swagger` version and non-empty `paths`; every message names the URL, and the timeout, network and JSON errors keep the original as `cause`), `cleanOperationIds` (camel-cases each ID and renames a later duplicate after its method and path), `sortArrays`, `addMissingPathParams`, `fixArrayItems` (gives an array that has neither `items` nor `prefixItems` the empty item schema `{}`, so kubb types it `unknown[]` and `z.array(z.unknown())`; without it kubb types the array as the empty tuple `[]`, per `arrays.test.ts`. Before `.changeset/untyped-array-items.md` it set `{ type: "string" }` there and on every `items: {}`, so the arrays the Vercel and v0 specs leave untyped, such as the feature flag variant `value`, `gitSources` and `deploymentSources` in `vercel-api-js` and the AST nodes of `experimental_content` in `v0-api`, were typed `string[]` and their zod schemas rejected any other item; live specs checked 2026-10-30), `fixUnionConstraints`, `camelCasePathParams`, `renameReservedWords`, `fixRegexPatterns`, `optionalReadOnlyInRequestBodies` (copies each component a request body reaches that marks a `readOnly` property required as `<name>Writable`, with those properties optional, and points the body at the copy, so responses keep the original; kubb itself omits a `readOnly` property only at the top level of a body and only when it is not a `$ref`. A `$ref` to a read-only component, such as Cloudflare's tunnel ID in a route body, does not count, as kubb also skips it: it doubles as a reference to that resource. Cases in `spec-transforms.test.ts`), `stripBasePathPrefix` (drops a base path that a spec path repeats; an operation already listed under the unprefixed path wins).
    - Enum values that are not identifiers (`10.x`, `!contains`, `*`, `#VERCEL_SKIP`, `0`) need no transform: kubb 5.13.1 writes them as quoted keys of the `asConst` object and lists them in the zod `z.enum` (`src/kubb/enums.test.ts`). `sanitizeEnumValues`, carried over from the earlier monorepo (b2d25f1), used to drop every string value that did not start with a letter, `_` or `$`, so `vercel-api-js` lost valid values from 164 enums of the live spec (2026-10-27), and an enum left empty became `unknown`, as for the `forceNew` and `skipAutoDetectionConfirmation` query parameters of `createDeployment`. Removing it from `packages/vercel-api-js/kubb.config.ts` changed only those enums in the generated output, and the regenerated client typechecks and passes its tests (2026-10-27); the scheduled run regenerates the committed client.
- `./effect` (`src/effect/index.ts`): the runtime side, shipped inside each client's `effect` entry.
  - Tagged errors `ValidationError`, `ApiError`, `NetworkError`, the `ApiConfig` context tag and `makeApiLayer` (`src/effect/errors.ts`). `ApiConfig` carries `token`, `baseUrl`, `fetchImpl` and `headers`, and `makeApiLayer` accepts all four (#46). `ApiError.message` is `API error <status>: <message>`, the message taken from the fetcher's `{ status, payload }` payload first and then the error itself (`message`, `error` as a string or `{ message }`, `errors[0].message`, or a text body), and falls back to `API Error: <status>`. `NetworkError.message` reads `message` from an `Error` or a plain object cause. `errors.test.ts` covers both (#33).
  - `createEffectApi` and `createEffectByPath` (`src/effect/proxy.ts`). Each operation runs in `Effect.tryPromise` and passes the `AbortSignal` it provides to the operation as `config.signal`, which the generated operation hands to the client's fetcher, so `Effect.timeout`, `Fiber.interrupt` or a lost race aborts the `fetch` instead of leaving it running. The proxies read only own keys, so `Object.prototype` names such as `constructor` return `undefined` (#46). Their types take the operation's params as `Omit<NonNullable<P>, "config">`; without `NonNullable` the optional argument of a generated operation made every Effect call accept any params (`.changeset/typed-call-params-*.md`). The params argument itself is optional when none of those fields is required (`EffectOperation` in `src/effect/proxy.ts`), as `RequiredKeys` makes it in each client's `client.api`; before, `ApiService.chats.chatsFind()` failed to compile and the READMEs passed `({})` (`.changeset/effect-optional-params-*.md`).

## Why it matters

A change here reaches every client at the next generation, and a change to `src/effect/` reaches every client's published `effect` entry at the next build. The `effect` peer is `^4.0.0` since [[decisions/2026-10-08-effect-4-major]].
