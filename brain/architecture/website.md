# Website

`apps/openapi` (`@sferadev/openapi-website`, private) is a Next.js app that lists the clients with install and usage snippets (`apps/openapi/src/app/page.tsx`). Changesets ignores it (`.changeset/config.json`).

- The page is statically rendered and revalidates every 6 hours (`revalidate = 21600` in `apps/openapi/src/app/page.tsx`). Each version it shows comes from the npm registry, and each lookup is cached for an hour (`apps/openapi/src/lib/npm.ts`), so a new release can take up to 6 hours to appear. A failed lookup renders `unknown` and logs one JSON line naming the package: `npm package not published` with `status: 404`, or `npm registry unavailable` with the other status, or a `reason` for a network, JSON parse or schema error.
- The registry lookup reads the full package document (`https://registry.npmjs.org/<name>`), not `/latest`, because only the full document has `time`, the publish date of each version (#343). It was about 0.5 MB for `vercel-api-js` on 2026-11-05; Next's fetch cache skips responses over 2 MB, so past that size each render fetches it again, which still works.
- Each home page tab shows the latest version's publish date and last week's downloads from `https://api.npmjs.org/downloads/point/last-week/<name>`, cached for an hour (#343). A failed downloads call logs `npm downloads unavailable` and the tab leaves the figure out. Dates and counts are formatted with a fixed `en-US` locale and the UTC time zone (`apps/openapi/src/lib/format.ts`), so the server HTML and the client render agree.
- The hero names the audience (TypeScript developers calling these APIs), says each endpoint is typed from the vendor's spec, and links the `Update OpenAPI` workflow so "regenerated" is checkable rather than a stated frequency (`apps/openapi/src/components/hero-header.tsx`, #343).
- The provider tabs (`apps/openapi/src/components/provider-card.tsx`) render the first provider on the server and on the first client render, then restore the tab stored under the `localStorage` key `activeProviderTab` after mount, ignoring a stored id that matches no provider. Reading storage during the first render caused a hydration mismatch, and the tab list wraps so it fits any number of clients (#48).
- Search and link preview metadata (#341): the root layout (`apps/openapi/src/app/layout.tsx`) sets `metadataBase` to `https://openapi.sferadev.com`, a canonical of `/`, Open Graph and a `summary_large_image` Twitter card, from the URL, title and description in `apps/openapi/src/lib/site.ts`. Every host that serves the build, `openapi-clients.vercel.app` included, therefore points its canonical at `openapi.sferadev.com`. The share image is `apps/openapi/src/app/opengraph-image.tsx`, rendered with `next/og` at build time; Next copies it and the title and description into the Twitter tags. `robots.ts` allows every crawler and names `sitemap.ts`, which lists the home page and every client page. A child page inherits the root canonical, so a new page sets its own `alternates.canonical` and joins the sitemap.
- Client pages (#342): `apps/openapi/src/app/[client]/page.tsx` prerenders one page per entry in the client list at `/<package name>`, such as `/vercel-api-js`, and 404s any other segment (`dynamicParams = false`). Each shows the title and description from `apps/openapi/src/lib/client-page.ts` (the API name plus `TypeScript client`), the not-affiliated notice, the install command, the client's `auth` text, and the live npm version, with links to npm, the package source and its `CHANGELOG.md`. Its examples are the first three `ts` blocks of the README's `## Quick Start` section, read by `apps/openapi/src/lib/readme.ts`, so a README edit changes the page with no second copy.
- A client page sets its own canonical and Open Graph URL. Setting `openGraph` drops the root `opengraph-image` that a child would otherwise get, so `clientMetadata` names `/opengraph-image` again; the build showed no `og:image` on the client pages without it.
- A client page revalidates every 6 hours like the home page and reads its README again each time, at runtime on Vercel. `outputFileTracingIncludes` in `apps/openapi/next.config.ts` traces `packages/*/README.md` into the `/[client]` function for that; a local `next build` lists all of them in `.next/server/app/[client]/page.js.nft.json`. Whether a revalidation on Vercel finds them there is unknown until one has run after a deploy.
- Each home page tab links to its client page (`apps/openapi/src/components/provider-card.tsx`).
- Each home page tab and client page links the upstream spec the client is generated from, labelled by `specLabel` in the client list, which names Keycloak's admin and account specs apart (`specLinks` in `apps/openapi/src/lib/client-page.ts`, #349).
- `llms.txt` and `llms-full.txt` (#347), following llmstxt.org: `apps/openapi/src/app/llms.txt/route.ts` and `apps/openapi/src/app/llms-full.txt/route.ts` are `force-static` route handlers that send `text/plain; charset=utf-8`, built by `apps/openapi/src/lib/llms.ts`. `llms.txt` links each client's README (raw on GitHub `main`), its npm page and the API it covers, then each `OPERATIONS.md` with the upstream spec it was generated from. `llms-full.txt` is the same text followed by every `packages/<name>/README.md`, read with `process.cwd()` at build time, so it matches the commit that was built; `turbo.json` lists those READMEs as website build inputs.
- The client list (`apps/openapi/src/lib/clients.ts`) holds each package name, the vendor, the API it covers, a sentence on how to authenticate and its `OPERATIONS.md` and spec pairs. `apps/openapi/src/lib/npm.ts` reads its package names from it, so a new client is added there once.
- `apps/openapi/AGENTS.md` is written by `next dev` and points agents at the Next.js docs in `node_modules/next/dist/docs/`; it is committed so the tree stays clean (#48).
- `GET /api/health` (`apps/openapi/src/app/api/health/route.ts`) runs `select 1` through the Drizzle `db` with a 3 second limit and returns `{ status, checks: { database } }`: 200 when it succeeds, 503 otherwise. A failure is logged server side with the driver error's name and message, never the connection string. The route is dynamic and sends `Cache-Control: no-store`, takes no auth and reads no new environment variables.
- Auth is Better Auth with a Vercel OAuth provider (`apps/openapi/src/lib/auth.ts`, `apps/openapi/src/app/api/auth/[...all]/route.ts`), stored in Postgres through Drizzle (`apps/openapi/src/lib/db.ts`, migrations in `apps/openapi/drizzle/`). The Vercel userinfo fetch and profile mapping live in `apps/openapi/src/lib/vercel-user-info.ts`, apart from Better Auth and the database so they can be unit-tested ([[development/testing]]).
- It imports no client package, so its build does not wait on any client build. The environment variables it reads, which `turbo.json` also lists for its build:
  - `DATABASE_URL`: `apps/openapi/src/lib/db.ts` and `apps/openapi/drizzle.config.ts`.
  - `AUTH_VERCEL_ID`, `AUTH_VERCEL_SECRET`, `AUTH_VERCEL_APP_NAME`: the Vercel OAuth provider in `apps/openapi/src/lib/auth.ts`.
  - `BETTER_AUTH_SECRET`, `BETTER_AUTH_URL`: read by Better Auth itself, since `auth.ts` passes no `secret` or `baseURL`.

## Hosting

The root `README.md` links the site at `openapi.sferadev.com`, and the repository's homepage field names a `vercel.app` address. Pull requests get a `Vercel` status that deploys a preview (for example #5), so the site deploys through Vercel's Git integration rather than a workflow in this repository; its project settings and environment live in Vercel, not here. The old `preview.yml` published package previews, not the site, and was removed in 8ff9fa1.
